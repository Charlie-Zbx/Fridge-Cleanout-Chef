# v0.2 架构说明

业务任务由后端SQLite维护：库存、偏好、提案、任务版本和确认回执。LangChain管理每次执行的模型—MCP工具循环；每次执行建立独立检查点，注入已确认状态和上一版摘要。同一业务任务的改条件通过revision连续，完整历史存run_revisions，不依赖把旧工具输出一直塞回模型。

MCP仍仅暴露search_recipes、get_recipe和evaluate_plan。每次执行由后端产生只读上下文临时文件；模型参数不能覆盖用户、库存或硬限制，工具没有写库存能力。服务端最终校验要求最终方案与真实工具通过的方案相同，使用的配方确实已读取。

DeepSeek文字和视觉适配、人数分批计算、提案确认、异步任务及部署接口详见[V2_GUIDE.md](V2_GUIDE.md)。并发限制在单进程内，额度及幂等记录持久化；公开部署必须保持单实例单worker。

照片只生成观察；提案有30分钟有效期和库存版本，确认时原子更新。add与set分开，未拍到的食材不删，同类重复观察需人工合并。原图仅在内存中处理。数量、包装标签、剩余比例都是待确认信息，不能当作精准称重或食物安全判断。

数据恢复及Render准备见[DEPLOYMENT.md](DEPLOYMENT.md)。当前验证边界及未完成事项见[STATUS.md](STATUS.md)。
