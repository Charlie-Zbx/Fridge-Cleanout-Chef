# 答辩演示脚本

## 启动前

在项目目录使用独立演示数据目录；不要清空真实厨房。默认KITCHEN_ENABLE_LIVE=0，启动 scripts/start.ps1，浏览器打开本地网页。确认“离线规则演示 · 无 API 消耗”可见。若使用真实模型，必须先说明当次调用预算并获得授权。

离线演示仍运行LangChain和真实stdio MCP，但模型决策为确定性替身，不能称为真实DeepSeek推理。现场真实请求失败时切换离线或展示保存的真实记录，明确说明来源。

## 案例一：正常规划和确认扣减

1. 新建测试浏览器会话，点击“用三种食材体验一下”：3个鸡蛋、200g卷心菜、300g豆腐，油盐和平底锅。
2. 保持1人、2顿、20分钟，允许待审核示例，点击安排。解释配方时间为开发估计。
3. 展示用量、步骤、预计时间和剩余；强调执行前库存不变。
4. 打开“做完了，确认实际用量”，在测试厨房提交演练用量，展示只扣一次。此操作不算实际做饭记录。

## 案例二：MCP发现冲突并修改

用新的测试会话重复上述库存，打开执行记录。离线替身会产生受控冲突，真实evaluate_plan指出问题，随后修正。指出search_recipes、get_recipe、evaluate_plan的参数与结果，以及最终宿主复核。

真实案例可展示 artifacts/change-live-1794086490737526700 中的五人重规划：旧组合超时后删减菜品并重新检查。展示前确认文件可打开；不要把离线替身与保存的真实模型结果混称为现场真实调用。

## 案例三：改条件和无解解释

1. 使用20个鸡蛋、1500g卷心菜、1500g豆腐，5人、2顿、90分钟规划。
2. 修改为每顿20分钟，保持其他条件；展示程序证明当前配方库没有可行单菜，并清楚说明限制。
3. 解释“无解”仅针对当前配方库和已确认条件，不代表现实中绝对做不出饭。

真实无解优化的前后记录见 LIVE_EFFICIENCY_TEST.md；调用减少来自确定性全库检查终止。不要把单次比较说成统计结论。

## 照片确认展示

用已授权图片现场识别，或展示本轮截图（明确为模拟视觉响应）：原图对照、种类待核对、数量需填写、重复需合并、取消不入库。切换和放大使用浏览器本地照片，不再次调用模型。未知食材不应强行映射。
