## 单张连通测试

`scripts/vision_smoke.py` 默认只在本地检查文件、哈希和图片格式，不发送请求、不创建库存记录。

```powershell
.\.venv\Scripts\python.exe scripts\vision_smoke.py --image-id gfp01
```

用户明确批准后才能临时开启真实调用，并追加 `--approve-max-calls 1`。只发送选定的这一张公开照片；最多一次视觉请求、最多3000输出token、总时限40秒、不自动重试。图片经应用正常预处理去除元数据并缩放后上传。脚本不会开启任何额外Agent请求，也不会修改库存。

每次执行在 `artifacts/vision-smoke-*` 保存输入来源、预算、观察结果和耗时/用量；失败也占用一次授权，不记录密钥、请求头或图片base64。首次失败后新增解析前的provider-result.json和具体校验字段诊断。初次成功结果也只能证明一次真实适配和定性表现，不能代表识别准确率。

## 第二次请求与核对结果

用户再次明确批准同图一次诊断请求。记录目录：`artifacts/vision-smoke-1794085723926381700`。请求1次、约4000毫秒，成功解析8条待确认观察，finish_reason=stop。输入2150token（其中缓存命中1920），输出642token，合计2792token；未查询实际账单。

- 找到标签清楚的脱脂牛奶，但同时将后方标签不清的瓶罐归为牛奶；该归类缺少直接证据。
- 正确保留锡纸容器内容未知，没有为遮挡蔬菜或瓶罐生成克数/毫升数；全部suggested_quantity为空，要求人工确认。
- 把可见甜辣酱误写为蔬果汁；这表明种类识别仍会出错。它未被强行匹配成菜谱目录中的食材。
- 未读出原图牛奶包装的3.78 L净含量；缩放后的可读性是可能因素，未另做验证，不能确认原因。
- 将同图独立油瓶分组为疑似重复，且部分品类、个数需要人工核对。

这是一次接口和解析成功，不代表完整库存识别准确，也无法解释第一次未保留原文的结构错误。两次视觉请求的结果分别保留，未丢弃失败记录。历史真实请求累计16次（14次文本＋2次视觉）；所有授权已用完。

基于以上问题已本地修改提示：不把前方标签套用到后方相似容器、不同包装不等于重复、依据清楚品名区分饮料与调味酱、目录外物品保持未知。确认页面显示原始标签/观察说明，并将数量标成“待核对”。**修改后的提示尚未通过新的真实调用验证，不宣称已经改善识别效果。**

将第二次原始响应保存为离线回放夹具（tests/fixtures/vision-gfp01-response.json）。API回放验证：识别不改库存，明确输入250 ml后才保存，未拍到的鸡蛋不变，重复确认不重复修改。250 ml只是合成的用户确认输入，不是原照片真实余量。视觉相关测试10/10通过；手机照片确认模拟测试通过；前端构建通过。
