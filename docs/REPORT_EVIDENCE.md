# 最终报告证据底稿

这是报告写作底稿，不是已经完成实证评估的提交稿。团队成员姓名、学号及课程格式另行填写。实做和用户材料回收后才能完成结果与讨论。

## 问题与目标

为自己做饭的年轻人和小家庭，根据已经确认的库存安排1–5人、1–2顿饭。降低选菜与清点负担，检查跨餐食材占用，减少不必要补买。当前项目没有测得真实家庭食物浪费下降，不能将产品目标写成实验结论。

## 系统与技术贡献

DeepSeek理解文字、观察照片并作出工具调用决策；LangChain组织单Agent循环及执行状态；FastMCP通过stdio暴露search_recipes、get_recipe和evaluate_plan。后端持有可信库存和硬限制，模型不能修改检查依据。

Python负责份量、整数计量、人数对应时间、跨餐库存和最终证据核对。React呈现确认与执行记录，FastAPI提供接口，SQLite保存会话、任务版本和幂等回执。系统不是单次菜谱问答；关键演示是“提出组合→工具指出冲突→修改→再次校验”。

照片产生观察而非库存事实。未知或矛盾种类清空预选，所有照片入库变更须人工核对种类及数量；服务器检查确认标记。来源图片在本次浏览器页面对照，服务端不保存原图。不支持食物安全判断、自动采购或营养处方。

## 待填的结果

- 20场景三组真实模型对照：完成率、硬条件违反率、修复率、耗时、token，按EVALUATION_PROTOCOL.md定义分母。
- 至少10组带实物真值的照片：错误类型、人工修改、未知项是否正确保留未知。
- 至少5个组合实做：人数、实际用量、时间、分批、口味与剩余。
- 3–5名熟人试用：全流程完成情况、耗时、求助与具体反馈。

## 局限与讨论

小配方库限制可行方案；耗时表在实做前仅为估计；遮挡和相似食材影响视觉可靠性；人工确认增加操作成本；单次或小样本结果不支持广泛泛化。未来迭代应由试用结果决定，不以增加Agent数量作为效果证据。
