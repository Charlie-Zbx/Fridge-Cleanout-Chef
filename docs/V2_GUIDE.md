# 余味 v0.2：人数、盘点与需求确认

在项目克隆目录完成依赖安装与前端构建后，双击根目录“启动本地项目.cmd”，打开 `http://127.0.0.1:8000`。首次安装见[本地安装说明](LOCAL_SETUP.md)。

## 本轮实现

- 1–5 人，1–2 顿，每顿最多三道菜。用量按基础份数缩放；按个计量向上取整，克/毫升向上保留两位小数。时间及批次读取固定人数表，顺序相加。原始菜谱没有三至五人时间表时拒绝静默放大。
- 30 道开发配方已补充人数表，全部仍是待审核估计，未伪装成人工审核或实做。当前分批表按每批最多两人份做保守开发估计，实际锅具、食材和菜式必须由团队核实；米饭等尤其需要按设备说明修订。
- 三个真实 MCP 工具保留，搜索增加分页；检查返回精简的冲突、用量和时间，不反复回传整套步骤。最终计划必须有实际搜索、配方读取以及完全一致的 MCP 检查通过记录，再由后端复核。
- 同一个业务任务可以继续修改；每次执行使用独立 LangGraph 检查点，并注入已确认状态和上一版摘要，避免把过期工具结果持续带回模型。最终版本完整轨迹另存 `run_revisions`。
- 浏览器通过 202 返回的任务编号查询进度。服务中断后标记 error，不自动重发付费请求。每次提交携带 request_id；同一个标识的重复请求不会启动新任务。
- 自然语言先生成确认卡片。离线模式是有限的规则解析器，只支持部分明确表达；真实模式使用 LangChain + DeepSeek，最多一次模型请求。两种模式都不会直接修改库存。
- 图片每批 1–3 张、每张最多 8 MB、合计最多 16 MB，缩放并去除元数据后上传；原图不落盘。支持整箱、分层和特写；记录可见数量、照片编号、包装文字、剩余比例、遮挡和疑似重复。
- 包装重量必须与模型读取的标签文字数值及单位相符，才能生成建议量；这是对输出的一致性检查，不等于 OCR 已被验证。没有依据、遮挡或疑似重复时不自动给出确定库存。
- 两个图片入口区分“新增”与“更新剩余”。确认时逐项选择更新、新增或保持；同类多条观察必须人工合并。未出现的库存不删除，过期或版本不符的观察不能保存。同一确认重复提交不重复执行。
- 手动盘点无需任何模型，可用于直接检查库存确认流程。库存变化使旧计划失效；做完第一顿后会重新检查剩余餐次。
- 团队审核与个人审核分开；个人审核绑定配方版本。实做记录独立保存，不因审核或评分自动增加实做次数。

## 无费用体验步骤

1. 使用示例库存，确认默认离线模式。
2. 在“补充想法”输入“改成五个人吃，每顿45分钟”，点击“整理这句话，先让我确认”。确认卡片出现前库存和偏好均未写入。
3. 在卡片核对人数及其他条件，点击“确认并保存”。
4. 点击“手动核对剩余”，将鸡蛋改成 1 个，其他两项保持，确认后应只剩 1 个鸡蛋，不会变成 4 个。
5. 根据实际库存规划；五人食材不足时返回无可行方案是正确结果。不要为了演示成功填写不真实库存。
6. 测试大份量可使用独立演示厨房和虚构测试库存：鸡蛋20个、卷心菜1000g、豆腐1500g，5人、每顿60分钟、允许待审核示例。此为软件测试，不代表膳食或口味验证。

## 接口增量

| 接口 | 行为 |
|---|---|
| POST /api/intake | message、preferences、mode、consent → 待确认的提案，不写库存 |
| POST /api/vision | files 1–3 张、purpose=add/stocktake、consent → 带依据的提案；兼容单 file 字段 |
| POST /api/stocktakes | 从当前库存创建手动盘点，无模型请求 |
| POST /api/proposals/{id}/confirm | inventory_version、changes、可选 preferences、questions_resolved → 原子确认 |
| POST /api/runs | request_id、preferences、message、mode、consent → 202 + 任务 |
| POST /api/runs/{id}/reply | 同上，增加 expected_revision；已确认餐次需另建任务 |
| GET /api/runs/{id} | 包含执行中的 trace、状态和完成结果 |

changes 的每项包含 ingredient_id、unit、quantity 和 action（set/add/keep）。同一食材不得重复；quantity 为0表示明确清零。提案有效期30分钟，并绑定创建时库存版本；确认后保存幂等回执。库存写入与偏好更新同一事务完成。

## 模型调用边界

`.env` 的真实调用总开关默认保持 0。已有密钥不代表已授权新的测试。规划最多六次请求/十二次工具/九十秒；整理最多一次请求；每批图片最多一次请求。所有 provider 请求无自动重试。

在线服务默认每浏览器用户每天20次、全局每天100次模型请求尝试，按 UTC 日期计数，数据库持久化；每轮发出前扣次数，失败也计数。全局最多两个交互任务，同一厨房最多一个。实验 CLI 使用另外的明确批次预算，不属于网页每日额度。
